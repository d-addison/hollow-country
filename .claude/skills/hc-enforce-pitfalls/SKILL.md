# Enforce Script pitfalls

Read the generated card first: `docs/pitfalls/enforce-pitfalls.md`. It lists every lint rule and every build-cited native
failure for this area. The card is generated by `tools/validate/pitfall_cards.py`; never edit it by hand, and
regenerate it after changing a rule message or a build-cited comment.

Before reporting done on a `.c` change:

- Flat function scope: one declaration per name per function, none in sibling blocks. No ternaries.
- No Enforce keyword as an identifier (`owned`, `out`, `inout`, `local`, `auto`, `ref`, `typename`, `thread`, `event`
  and the rest of the card list), no method named `Wait`, no bitwise operator inside a float expression.
- `ref` for owned arrays and maps. Hold a fresh call result in a local before passing it on.
- A removed field or a changed override signature breaks other files of the modded-class chain: search them and
  copy native signatures from the installed scripts cache.
- Run `enforce_lint` and `enforce_perf --strict-baseline` (new=0); both are source checks, the native compile
  gate is the truth.
