# Tick and performance

Read the generated card first: `docs/pitfalls/perf-tick.md`. It lists every lint rule and every build-cited native
failure for this area. The card is generated by `tools/validate/pitfall_cards.py`; never edit it by hand, and
regenerate it after changing a rule message or a build-cited comment.

- Work is bounded per tick: charge HCWorkBudget, never scan a whole collection or loop over all players in one tick.
- Register every work slot completely, with one owner class per slot (HC-P006, HC-P007).
- No per-item Print on a tick path, no synchronous store Save, no file I/O outside the staged writer.
- Use HCSaveScheduler for saves, HCModuleReadiness for the ready and use lines, HCPerfConfig and the settings
  registry for tunables.
- A raw `HCTake` bypasses consumer fairness and attribution; go through the budget API.
- Check with `enforce_perf --strict-baseline` (new=0); the real cost shows in the soak `[HC TickCost]` lines.
