# Persistence

Read the generated card first: `docs/pitfalls/persistence.md`. It lists every lint rule and every build-cited native
failure for this area. The card is generated by `tools/validate/pitfall_cards.py`; never edit it by hand, and
regenerate it after changing a rule message or a build-cited comment.

- The friend server can never be wiped: a stored-format change needs a migration that runs at start.
- Every on-disk state loads or self-repairs; never refuse forever. A failed repair is retried a bounded number of
  times, then proceeds on the last complete state with one reason-code line.
- Never delete the only copy of data without a verified preserve. Verify by byte count, not string length.
- No receipt is lost, no loot is duplicated across a restart; write through HCSaveScheduler and the staged writer,
  one native file operation per step, chunks well under the native 8 KiB per-call transfer cap.
- JSON-loaded scalars get an explicit zero or default guard; a literal-only initializer, never a computed
  static const.
- The brief for a persistence change carries a design review line and a failure table of every cut point.
