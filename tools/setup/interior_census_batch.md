Launch a runtime only once: use either the sequential runner or an individual
launch, since profiles/storage must be fresh. Detached native operation remains
for the lead to verify; offline tests only check the generated files and plans.

The generated runner invokes its copied `Start-CEProbeServer.ps1` once per planned
run, with `-Kind interior-sampler -Runtime D:\HollowCountryLocal\interior-sampler-321-r1-N`,
then once with `-Kind ce-probe -Runtime D:\HollowCountryLocal\ce-probe-321-r1-treatment`.
It runs sequentially and stops on an incomplete observation. The existing launcher
checks hashes, fresh storage/profiles, no running server and the executable pin,
waits for each sentinel and stops only the process it started. It starts no client.
Use a new `--tag` for another complete fresh batch; substitute it in all commands.
Do not reuse or remove a failed runtime to pretend it was a fresh observation.

The issue preset is data in `interior_census_support.ISSUES`. Census targets include
the issue's named refusals and treatment classes, the existing sampler calibration
classes (with their stock floor points inlined into the existing frame-check hook),
plus **every classed WRP wreck
without a stock prototype group**. This deliberately also surveys the three copied
wreck groups (UAZ, tractor, closed trailer). The installed config supplies canonical
class spelling; the pinned WRP supplies positions, checked against every stock
placement. Observation targets do not add CE groups or rows to the census mission.
A missing class/placement refuses staging instead of silently omitting it.
`batch-plan.json` lists every class, run, target and deterministic native run id;
`classes.json` and `evidence.json` retain the selection and provenance.
Census runs contain at most 64 targets; `--run-size` can lower that budget.
The exact census counts and native run ids come from the generated `batch-plan.json`.
The census retains one placement per class; `--treatment-per-class` only changes
CE treatment sampling. These plans are input checks, not native observations.

Treatment is generated by the **existing `loot_boost.plan` packaging writer** with
its committed shipped points and default floor policy. It reads only the verified
vanilla stock-backup mission. All returned XML deltas are staged, including
`mapgrouppos.xml`, types and globals, so the new groups and type tags coexist.
The treatment uses the same existing CE probe hook with every group derived through
`new_buildings.shipped` / `new_buildings.parse` from the committed
`mission/hollow-country/loot-points/new-buildings.json`. There is no separate class list.
`--treatment-per-class` defaults to 3 and accepts 1 through the sampler's
`MAX_PER_CLASS` (currently 16). Positions are selected deterministically from the
**packaged** placements. Classes with fewer placements use all available positions;
zero placements or a missing prototype group refuse staging. The treatment's
`sampling` record in `evidence.json` and `ce-probe-plan.json` includes the requested
per-class count, every class's available/selected count, shortfalls and target total.
If the total exceeds the CE probe's `HARD_CAP` (currently 400), preparation refuses
before writing any runtimes, with a message to lower `--treatment-per-class` or split
the treatment into separate staged runs. No class is silently dropped.

The current 11 shipped groups produce **29 targets** at the default of 3:
Office_Municipal1 and Wreck_C130J_2 each have only one placement; all other groups
supply three. The treatment prototype and position bytes are exactly the packaging writer's output on that verified stock
baseline at the recorded commit. This is a loot-layer treatment, not a full modded
release boot. `evidence.json` and `ce-probe-plan.json` record commit, generator and
every replacement SHA-256; staged-file hashes are rechecked by the launcher.

## Ingest using the existing #227 path

After the launcher finishes, run this WSL command from the same checkout. It reads
run indices from the plan, requires each completion sentinel and passes the raw
censuses to the existing `interiors_profile coverage`/`interior_templates.load_census`
admission path; it does not fabricate a merged native run:

```sh
python3 -B - <<'PY'
import json
import subprocess
from pathlib import Path
from tools.setup import probe_runtime as rt

root = rt.WSL_PARENT
batch = root / 'interior-batch-321-r1'
plan = json.loads((batch / 'batch-plan.json').read_bytes())
stock = Path(rt.DEFAULT_SOURCE_RUNTIME) / 'stock-backup/mpmissions' / rt.MISSION_NAME
args = ['python3', '-B', 'tools/package/interiors_profile.py', 'coverage',
        '--proto', str(stock / 'mapgroupproto.xml'), '--pos', str(stock / 'mapgrouppos.xml'),
        '--batch-plan', str(batch / 'batch-plan.json')]
for run in plan['runs']:
    args += ['--census-dir', str(root / ('interior-sampler-321-r1-' + str(run['index'])))]
subprocess.run(args, check=True)
PY
```

Expect `[HC Interiors] batch plan runs=<N> done=[<all planned indices>] missing=[] runtime=PENDING`
and `census_rejected=0`. Stock coverage retains its stock denominator: newly surveyed
classes without stock groups do **not** automatically become accepted templates or
loot points. For a template rebuild, pass those same `--census-dir`/`--batch-plan`
arguments to `interiors_profile.py templates build` with `--proto`, `--pos`, `--types`
and a fresh `--out`, as for #227. Preserve raw census files, hook plans, sentinels and
logs outside Git for the lead's point-authoring and upper-floor review.
